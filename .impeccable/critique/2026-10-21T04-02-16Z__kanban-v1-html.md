## Design Specificity Verdict

The complaint is correct. The pill-ification is a departure from the product's own vocabulary: .qa-stat--over in css/variants.css already expresses "overdue count" as a demibold error-red numeral with a middot separator and no chip, and v2's header uses exactly that. v1's chip came from neither the Figma frame (which had View all in that slot), nor the design system, nor the sibling screen. The CSS comment justifying the chips as "the language of its tinted task blocks" is asserted, not built: those blocks are 8px-radius rectangles with an icon and a left-aligned label.

The row traded an action for a statistic and kept the action's clothing: a bordered, tinted, pill-shaped token reading "4 overdue" is the standard promise of a filter chip, and nothing happens on click.

It carries none of the product's stage vocabulary. MASTER_STAGES ships a colour per stage and glyph 'clock' for Snoozed; the work-list group header uses both; the kanban header uses neither.

Not a tell: (03). The zero-pad is house style (five uses across variants.js and popups.js).

Deterministic scan: null result, not a clean bill. detect.mjs exited 0 with an empty array but reported itself DEGRADED (htmlparser2, css-select, css-tree, domutils unavailable; no custom-property, selector or contrast evaluation), and kanban-v1.html is a 21-line shell whose body is injected at runtime, so a static engine has nothing to read. Installing the parser packages into the plugin dir was refused by the permission classifier; not routed around.

In-page overlay ran and found 4 anti-patterns, none inside the header: two cramped-padding (artboard root and nav placeholder, both false positives, scaffolding), one flat-type-hierarchy at document level (false positive, the header's 16/600 vs 14/600 is a deliberate two-step), and one real low-contrast 3.6:1 on the toolbar KZ avatar (white on brand-400) which is out of scope but real, and a token-pairing fault rather than a hardcoded bypass.

That the mechanical pass found nothing in the header is the finding: this is a composition problem, not a lint problem.

Contrast correction: 16px demibold is NOT WCAG large text (large needs 18.66px bold or 24px), so .kb-col__n needs 4.5:1 and measures 3.95 (grey), 3.84 (newlead), 3.14 (snoozed). Fails AA in all seven columns.

## Overall Impression

Tidy, and that is the problem. It reads as reasoned-sounding and unexamined: comments justifying choices the live page contradicts, a component invented where the system already had one, and domain vocabulary stripped out. Biggest opportunity: stop drawing chips, speak the pipeline's language, which v2 already does.

## What's Working

1. Totals are derived, never authored. kbColumnStats sums the same array kbColumn filtered, so the header cannot disagree with its cards.
2. Zero-suppression of the overdue pill is the right instinct; it needs a threshold rather than a zero test.
3. The header is pinned above the scroller, so stage identity survives a long column scroll.

## Priority Issues

[P0] The overdue pill vanishes on New lead and shouts on Snoozed.
.kb-stat--over fills with error-bg; the New lead ground is error-bg. Measured fill contrast 1.00. Only a 1px border at 3.08:1 separates them, and on Snoozed that border drops to 2.51:1, under the 3:1 non-text minimum, while both pills gain maximum prominence. The CSS comment claiming "both carry a border so they hold up" is false: the white pill's border measures 1.07-1.15:1 against every ground.
Fix: drop the fill, use ink. Error-red demibold on the column ground, no chip, matching .qa-stat--over.
Command: /impeccable colorize

[P1] Red fires on 7 of 7 columns; the rationale is defeated by its own data.
Overdue counts are 2,4,2,2,4,2,1, so the suppression branch never executes. kbState() rations card alerts to 12 of 27 deals deliberately; the header overrides that at a glance.
Fix: threshold it like the cards, or count deals overdue rather than tasks overdue.
Command: /impeccable quieter

[P1] The row speaks none of the pipeline's vocabulary. This is the "AI" tell.
No stage colour dot, no clock on Snoozed, though both are in MASTER_STAGES and used by the work-list group header.
Fix: reuse .vx-dot with g.colour and the glyph branch.
Command: /impeccable typeset

[P1] "2 overdue" names the wrong unit, and the count fails AA.
The number sums d.tasksOverdue but drops the noun; New lead reads "2 overdue" over 3 cards. v2 says "2 tasks overdue" and is correct. .kb-col__n fails 4.5:1 in all seven columns.
Fix: say the noun; take the count to text-secondary.
Command: /impeccable clarify

[P2] Looks interactive, is not, and is invisible to assistive tech.
Measured: 0 focusable elements, 0 headings page-wide, 7 sections with no accessible name. Screen reader reads "Qualifying, open paren zero three close paren, dollar one point two M, four overdue". The header also sits on no grid: the name starts 25px from the column edge while cards start at 14px, and the stats end 12px inside the cards' right edge.
Fix: stage name as h2, aria-labelledby on the section, zero the 11px left pad, and either make the overdue count a real filter or strip its chip clothing.
Command: /impeccable audit

## Questions to Consider
